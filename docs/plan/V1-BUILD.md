Plan deck: https://claude.ai/artifact/64PSRbxtPTXLU4ioTk4rLY. This repo is 1.0. `<2.0 repo>` is 2.0 (every feature, untouched): **copy from it, never rebuild** (D-031). Orchestrator: the main session. Builders: one card each, in parallel.

## The product in one paragraph

A small company with domain knowledge and no data team. One **decision maker** fills a company page and talks to **North** (industry expert) in one thread, dropping sample files and documents in as they go. North asks few but relevant questions and writes a **statement of work** (SOW): goal and why, the process map, the KPIs with definitions, the source systems, a data catalogue that covers the structured samples *and* the unstructured documents, governance rules, and an unclear list. One signature. **Span** (architect) drafts three layers, scans the sources per KPI (available / partly / not), the decision maker agrees the scope, Span writes the **ETL mapping sheet**. **Flow** (data engineer) loads from the sheet with the built-in runner. The **ops manager** confirms "Loaded" per period, which opens the **Consume centre**: KPI cards as signed, plus an **offer card** ("with a market data feed you would also get…"). **Nira** orchestrates the agents in a **room** per intent where the agents talk to each other and people can read and answer. The **map** stays: this intent solves this problem from these sources through these KPIs.

Out of 1.0: walls, rooms for people, brainstorm, check-in, Problem, Decision, radar, hypotheses, change-note chain, proving report, invitations, seats and visibility tiers. Their code stays in the copy; 1.0 simply does not link to it (nav, home, permissions).

## Rules for every builder

1. **Own files only.** Backend: `sh_platform/v1/<card>_routes.py` (exports `router`), `sh_platform/v1/<card>.permissions.yaml` (a `routes:` block in route_permissions.yaml's shape), `sh_platform/v1/<card>_*.py` for logic. Screens: `ui/src/v1/<card>/routes.tsx` exporting `routes: V1Route[]` (paths relative to `/centre`, literal), pages and components beside it. Tests: `tests/v1/test_<card>.py`, `ui/src/v1/<card>/*.test.tsx`. **Never edit** app.py, App.tsx, route_permissions.yaml, the manifests, `ui/src/api/client.ts`, `ui/src/styles/*`, the shell, or another card's folder. Need something there? Write it under "Shared edits needed" in your report; the orchestrator does it.
2. **Copy from 2.0.** Start with a reuse check naming the 2.0 files and line ranges you copy (`graft ask` in the 2.0 repo works: `cd "<2.0 repo>"`). Import kernel modules from this repo (`sh_platform.plane`, `sh_platform.jsonfile`, `sh_platform.agents.*`, `sh_platform.build.agents.runtime`, `sh_platform.graph`, …) rather than copying them.
3. **Records are the contract** (below). Never invent a field; a missing one goes under "Open questions" in your report.
4. **Agents draft, people act.** Every model call goes through the runtime and the egress gateway (`sh_platform.build.agents.runtime.runtime_for_plane` or `sh_platform.agents.loop.run_agent`); when the model is off (`SH_MODEL_PROVIDER=off`) a rule-based fallback runs and is labelled. Nothing is signed by an agent. Figures trace to a run or say "Not available yet".
5. **No servers.** Test with FastAPI's TestClient and vitest only. Do not start uvicorn or vite; the orchestrator serves 8400/8401. Data for tests: copy `data/` to a tmp path (see `tests/auth/test_role_matrix.py::world`).
6. **Light testing.** One test file per card proving the main path and one refusal. No persona rounds, no screenshots.
7. **Copy and data rules.** British spelling, no vendor or model names on screen, synthetic data only, no Claude attribution anywhere. Company: `neera` (ten people, data loaded) for everything; `fresh` (empty, one owner) must not break.
8. **Report** to `docs/plan/v1-landings/<card>.md`: reuse check, what landed (files), how to test by hand (sign-in, clicks), shared edits needed, open questions. Then stop.

## Records (the contract). All under the company plane, JSON via `sh_platform.jsonfile`.

**Thread** `intents/<iid>/thread.json`: `{"intent_id", "turns": [{"id", "by": "person"|"north", "name", "text", "at", "need": "goal"|"process"|"inputs"|"kpis"|"rules"|"unclear"|null, "files": [{"name", "path", "kind": "sample"|"document"}]}], "needs_done": ["goal", …], "state": "open"|"sow_ready"}`.

**Statement of work** `intents/<iid>/sow.json`:
```
{"id", "intent_id", "title", "state": "draft"|"signed", "version",
 "goal": {"line", "why", "readers": [], "decisions": [], "needed_by"},
 "process": {"steps": [{"n", "name", "who", "does", "inputs": [], "outputs": [], "system"}], "handovers": [{"from_step", "to_step", "what"}]},
 "kpis": [{"code", "name", "definition", "formula", "unit", "period", "owner", "source_ids": [], "status": "defined"|"unclear", "pack_suggested": bool}],
 "sources": [{"id", "name", "kind": "file"|"system"|"document", "holds", "sample_path", "owner", "fields": [{"name", "type", "example", "meaning"}]}],
 "catalogue": [{"table", "layer": "landing"|"silver"|"gold", "meaning", "source_id", "fields": [{"name", "type", "meaning", "source_field"}], "feeds_kpis": []}],
 "governance": [{"rule", "kind": "access"|"retention"|"approval", "applies_to": [], "stated_by"}],
 "unclear": [{"id", "question", "about", "who_can_settle", "settled": bool, "answer"}],
 "signature": {"name", "role", "at"} | null,
 "signatures": [{"name", "role", "at", "version"}]}
```
`signatures` keeps every signature ever given (added by I4): when an offer reopens a signed record, `signature` clears and the history stays.
A document source (`kind: document`) carries what was read from it: definitions, owners, systems, rules, each with the file name and a short quote. Signing freezes the record (rule 7) and writes the KPI definitions to the glossary and the catalogue rows to the catalogue through the 2.0 stores, both marked signed.

**Scan report** `build/scan/<iid>.json`: `{"intent_id", "at", "kpis": [{"code", "status": "available"|"partly"|"not", "sources_used": [], "missing": [{"what", "where_expected"}]}], "agreed": {"by", "at", "scope": [codes]} | null}`.

**Architecture** reuse 2.0's `build/blueprint.json` and `build/architecture/record.json` (three layers, components per KPI).

**Mapping sheet** `build/mapping/<iid>.json`: `{"intent_id", "version", "rows": [{"n", "layer", "target_table", "target_field", "source_id", "source_table", "source_field", "transformation", "rule", "test", "status": "mapped"|"unclear"}]}`; exported as `.xlsx` (openpyxl is installed).

**Runs** reuse 2.0's `warehouse/runs.json` and the runner (`sh_platform.build.runner`). **Loaded** `build/ops/loaded.json`: `{"periods": [{"period": "2026-09", "source_id", "state": "loaded"|"not_loaded", "reason", "by", "at"}]}`.

**Agent room** `intents/<iid>/room.json`: `{"intent_id", "posts": [{"id", "by": "north"|"span"|"flow"|"watcher"|"nira"|"person", "name", "to": [agents or "people"], "kind": "handover"|"question"|"answer"|"nudge"|"note", "text", "at", "refs": [{"kind": "sow"|"scan"|"mapping"|"run"|"loaded", "id"}]}]}`. `sh_platform/v1/room.py` (card X1) exposes `post(plane, iid, by, kind, text, to=…, refs=…)`; every other card calls it at its hand-overs (import guarded: a missing room never breaks a card).

**Map** reuse 2.0's graph (`sh_platform/graph`): nodes intent, problem, source, kpi, table; edges solves, uses, feeds, defines.

## Round 2 (8 October): the Intent Centre is one conversation

Nitin's direction: the Intent Centre is **one screen, a conversation with North**, the way a person talks to an assistant. No forms, no six fixed needs. North drives: it knows the industry (pack) and the company (company page, documents), asks one thing at a time, builds on what it already knows, proposes instead of asking when a document or a file answers, draws the process map and iterates it, and drafts the statement of work live beside the chat, iterating it with the person until both are content. About fifteen minutes of talk should yield an SOW an architect can build from. Model: the Google model already wired through the runtime; the rule-based fallback exists only when the model is off, labelled.

What North must cover in the talk (its goals, not a script; it may cover several in one exchange and skip what the context already answers): what the person wants to build and why; how it is produced today (sources, extraction, manual steps, transformations and manipulations, who does what); what the end result should look like; how often it should run; which sources are strategic; whether unstructured data is involved (and asks for the documents); the KPIs and how each is worked out today; rules (who sees what, retention, approval); what is still unclear and who can settle it. It closes with "Here is the statement of work as I understand it; shall I hand it to the architect?"

### V1 Search by meaning (hybrid RAG)
Decision (Nitin, 8 Oct, "go vector"): North and the other agents find passages by meaning as well as by words, with a local embedding model downloaded once.
- **Local only**: `fastembed` with `BAAI/bge-small-en-v1.5` (quantized ONNX, ~70 MB) cached in `data/_models/`, loaded lazily once per process. Whole documents never reach a cloud embedding API; the only network use is the one model download from Hugging Face.

- **Backfill**: files indexed before this card get vectors at the first search (background, at most 4 files per search); `tools/reindex_vectors.py <company> [--all]` does it at once.
- **Access unchanged**: vectors are queried only for the paths `doc_tools` passes in (ticked, readable).
- Tests: `tests/v1/test_vectors.py` with a stub embedder (synonym, fusion order, fallback, change re-embeds, other paths never returned, backfill).
