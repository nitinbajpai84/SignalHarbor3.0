## What landed

- `sh_platform/v1/b2_scan.py`: holds the scan logic. It reads every CSV and every XLSX sheet under `landing/` (headers and data-row counts), builds what each KPI needs from the signed SOW and writes `build/scan/<iid>.json` in the contract shape.
  - **What a KPI needs:** the fields of the catalogue rows whose `feeds_kpis` name it. Landing-layer rows are used when there are any, otherwise all of its rows. For each field the scan takes `source_field`, or `name` if that is empty. If no catalogue row feeds the KPI, it falls back to the fields of the sources in `kpi.source_ids`.
  - **When a field counts as present:** a landing file (or sheet) has a column with that name and at least one data row. Names are compared without case, spaces or punctuation. The scan looks first in the source's own files: a folder or file stem that matches the source id or name, or the file name of `sample_path`. If the source has no files of its own, it looks in every landing file.
  - **Status:** all fields found means available, some means partly, none means not. A KPI with no field named at all is not, with a missing line saying so.
  - **Re-scanning** resets `agreed` to null.
- `sh_platform/v1/b2_routes.py` adds four routes:
  - `GET /api/v1/build/{iid}/scan`
  - `POST /api/v1/build/{iid}/scan` (needs a signed SOW: 409 if it is not signed, 404 if there is none)
  - `POST …/scan/agree` with `{scope: [codes]}`. It returns 422 if the list is empty or names a code that is unknown or has status not, and 409 if there is no scan yet.
  - `POST …/scan/send-back` with `{reason}`. It clears `agreed` and posts to Span.
  - Every response is `{scan, names, files}`: the record, the KPI names from the SOW and the landing files that were read.
  - Room posts use a guarded import of `sh_platform.v1.room.post`. After a scan, Span posts a hand-over to people. After agree, Span posts a hand-over to flow and people. A send-back is posted as a person's question to Span.
- `sh_platform/v1/b2.permissions.yaml`:
  - GET: every company role.
  - Scan: company_admin and analyst (the architect seat).
  - Agree and send-back: company_admin and sponsor (the decision maker seat).
- Screen `ui/src/v1/b2/` (`routes.tsx`, `ScanPage.tsx`, `api.ts`, `ScanPage.test.tsx`), at `/centre/build/:iid/scan`:
  - a row per KPI: tick box, code and name, status pill (Available / Partly / Not available yet) and what is missing with where it was expected
  - the line "These N of M can be built now"
  - Agree (scope is the ticked KPIs; it starts with the available ones, and KPIs with status not cannot be ticked)
  - Send back with a reason, and Scan / Scan again
- `tests/v1/test_b2.py` (2 tests) covers:
  - available, partly and not, worked out from a CSV and a two-sheet XLSX fixture
  - agree written to disk
  - refusals: an analyst agreeing gets 403, a scope that names a KPI with status not gets 422, scanning a draft SOW gets 409
  - The fixture sets its own test passwords on a tmp copy of `_control`, because `seed_credentials.txt` was rewritten without the Neera lines while I was working (21:54, probably by a reseed).

## Open questions

1. The scan record has no field for landing files or row counts. Row counts are used only to decide presence (a file with a header but no rows does not count), and the file list is returned in the API response, not stored.
2. The contract says "present in a landing file". So a column that exists in some monthly files but not others still counts as present. D1 planted a column renamed mid-year (positions_2026-01 has 7 columns, the other months 8), and the scan does not flag it. Should "partly" also cover a field missing in some periods?
3. `room.post` takes no `name`, so the send-back post is `by: "person"` with the person's name in the text. Should X1 accept a `name`?
4. The screen shows column names and landing paths in "what is missing". That is the point of the scan, but it bends the "no table names" copy rule. Should the screen use the SOW field meanings instead?
5. Is send-back expected to do more than clear `agreed` and post to Span, for example move the SOW back to draft? The contract has no field for it.
