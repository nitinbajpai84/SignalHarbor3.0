## What landed

- `sh_platform/v1/c1_cards.py`: logic. Reads `intents/*/sow.json` (state `signed` only), `build/scan/<iid>.json`, `build/ops/loaded.json`, `warehouse/runs.json`, gold marts.
- `sh_platform/v1/c1_routes.py`: `GET /api/v1/consume` -> `{intents: [{intent_id, title, signature, kpis: [{code, name, definition, unit, owner, period_kind, table, source_ids, latest, trend, range_break, reason}]}]}`; `GET /api/v1/consume/{iid}/{code}?period=YYYY-MM` -> `{value, table, runs: [{source_id, run}], pipeline, columns, rows}` (50 rows max); 404 "Not available yet" when the KPI is unknown or the period is not loaded.
- `sh_platform/v1/c1.permissions.yaml`: both routes for all six company roles (the Consumer seat).
- `ui/src/v1/c1/routes.tsx`, `ConsumePage.tsx`: `/centre/consume`, one section per signed SOW, a card per KPI; a loaded card is a button that opens the run and rows panel.
- Tests: `tests/v1/test_c1.py` (2 passed: main path on a tmp copy of Neera's warehouse; refusal of a not-loaded period and a signed-out caller), `ui/src/v1/c1/c1.test.tsx` (1 passed). `tsc --noEmit` clean for c1.

Rules as built:
- Gold table per KPI: the SOW catalogue row with `layer: gold` whose `feeds_kpis` holds the code; else the mart named after the code (`K01` -> `gold.k01`, which matches Neera's 27 marts).
- A period shows when every `source_id` of the KPI has its newest `loaded.json` line `loaded` for that period. A KPI with no `source_ids` needs one `loaded` line and no `not_loaded` line for the period.
- Reason when nothing shows, first that applies: scan status partly/not with its missing lines; not in the agreed scope; the newest `not_loaded` line and its reason; no figures in the warehouse; not scanned yet; no period marked loaded yet.
- Run for a figure: per source, the first run in `runs.json` started in or after the period's month.

## How to test by hand

Needs a signed SOW (I4), a scan (B2) and at least one Loaded period (B5) on Neera first; until then the page says "No statement of work is signed yet".
1. Sign in as Dev Sharma (participant) or anyone at Neera; open `/centre/consume`.
2. A KPI with a loaded period shows value, month, sparkline, owner. One without shows "Not available yet" and the scan's reason.
3. Click a value: the panel shows the run that loaded it (status, source, date, rows) and the mart rows for that month. Close.
4. As Leela on `/centre/build/ops`, mark the next month Not loaded with a reason: the card keeps the previous month; a KPI with no loaded month shows that reason.
Fresh: the page shows the empty state (checked: `build()` returns `{intents: []}`).

## Open questions

- SOW `governance` rules (kind `access`) are free text with `applies_to`; the contract has no viewer list per KPI, so C1 does not restrict values per viewer (2.0's `may_see`). Every company role sees every loaded KPI.
- `loaded.json` has no rule for which run belongs to a period; C1 takes the first run on or after the period's month. B4/B5 may want a `run_id` on each loaded line.
- The contract does not say whether a KPI outside the agreed scope may still show a loaded value; C1 shows it if loaded and otherwise gives "Not in the agreed scope" as the reason.
