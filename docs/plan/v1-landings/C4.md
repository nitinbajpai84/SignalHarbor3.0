## Open questions

- `uploaded_by_id` (the uploader's account id) is added to each index row so ownership does not rest on display names, which can repeat. The contract lists only `uploaded_by`. It is never sent to the screen; the screen gets `mine` and `can_change` instead.
- Files dropped through the composer's paper-clip still go to the thread (`landing/` or `documents/` via `save_file`), as before. They do not become library items, so they never appear for others. Should they also be registered as private library items ticked for the conversation?
- Ticking does not start a catalogue scan; the ticked items reach `sow.sources`/`catalogue` at the next scan (file drop, ready, sign). A scan per tick would read every document again through the model.
- Seeded items cannot be made private (they came from the company's own folders); a company_admin may delete their index row (the file in `documents/` or `landing/` stays).
- The note can be changed through `PUT /api/v1/library/{id}`; the box has no inline note editor yet.
- An intent from before the library, with no `context.json`, shows as ticked the library items its SOW already reads from (matched by path) until someone ticks or unticks.
