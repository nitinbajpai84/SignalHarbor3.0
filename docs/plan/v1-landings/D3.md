# D3 Structured sources: landing

## Reuse check
`docs/reuse-inventory.md` has no sample or synthetic-source generator; the earlier repo's `tools/` has none either. `tools/make_samples_neera.py` (D1) reads the Neera warehouse, so it cannot be reused for a new company; its CSV writing and copy-to-samples pattern were followed. New: a self-contained, seeded simulation (prices, FX, indices, trades, income, fees, calls, tax lots) so every file ties to every other.

## What landed
- `tools/make_samples_fo_demo.py`: `python tools/make_samples_fo_demo.py [company_id] [company_name]`; id defaults to the plan's id, the name defaults to the id title-cased without its number (so the name never appears in code). Deterministic and idempotent (same seed, same files; re-run checked by hash), about 5 s.
- `data/<company>/landing/`: 18 folders, 186 files (1.5 MB) plus one `_manifest.json` per folder; same tree copied to `local/samples/<company>/`. Daily files kept to the plan's sizes: positions about 42 rows a day, prices about 1,000 rows a month, 22 to 70 ledger rows a month.
- `docs/product/FO-DEMO-SOURCES.md`: every folder, pattern, columns, owner, frequency, PRD use case and how the numbers tie.
- `docs/product/FO-DEMO-ANSWER-KEY.md`: written by the generator with the exact values of the ten planted truths. The generator asserts the drift and concentration plants (first breach day, never before, always after) and that no custodian or bank balance goes negative.

## How to test by hand
Run the generator; open `docs/product/FO-DEMO-ANSWER-KEY.md` and, for any truth, open the file it names (for example `custodian_transactions/custodian_transactions_2025-12.csv` and search the duplicate reference). Point the catalogue scan at `data/<company>/landing/` and compare its exceptions with the key.

## Shared edits needed

## Open questions
- TWR perimeter is the listed portfolio (three custodian accounts); calls and distributions are treated as external flows. Drift and concentration include private funds at the latest reported NAV. Both are stated in the key; change if the IPS (D4) says otherwise.
- MWR is not in the key (not a planted truth); the ledger and portal carry the flows to compute it.
- No merger in the corporate actions file (the plan lists it as an allowed value, not a required row).
