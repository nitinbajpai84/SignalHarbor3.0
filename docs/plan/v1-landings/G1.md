## The rules as built
- full: the people named on the project (`people` parts plus `team`) and every company_admin. read: a person any comment on the project is addressed to (S10, whatever their role), a live grant, the ops seat once the project is live, and everyone signed in when the project is Open. preview (Internal, not a member): title, stage, owner, "Request access". none (Restricted): only `{id, locked, can_request}` when asked for by id; not in the list.
- Open and read-only: the design, build pack, run book and benchmark sheet may be read, but their export needs company_admin, analyst or sponsor (what a1/b3 allow) unless the viewer is full.
- A project saved before G1 has no `sensitivity` and reads as Open, so nothing existing changes. New projects start Internal.
- Trail notes about access (granted, taken back, set to Restricted) are addressed to nobody, so a note never gives anyone access.

## Every project read now goes through the helper (sites)
1. Artefact view: `p1_routes.get_artefact` (`G1.require`).
2. Export: `p1_routes.export` (`G1.require` + `G1.export_allowed`); a full-level export is also kept in `projects/<pid>/files/`.
3. Project page and lists: `p1_routes.list_projects`, `of_intent`, `get_project` (`G1.shown`: whole or lock row).
4. Comments: `p1_routes` list, add, answer, resolve (`G1.require "read"`; S10 holds because an addressed comment gives "read").
5. Pulse: `p2_pulse._compute` (`G1.level`; Internal shows a lock line with no cards; the old role test is gone; the "not signed yet" rule stays as a state rule); new card kind `access` ("Approve / Not now") for the owner.
6. Company map: `m1_map.add_company_map_nodes` calls `G1.restrict_nodes` (a Restricted project's own nodes are a silhouette to everyone off the team; company admins are on the list).
7. Benchmark sheet and source viewer: `g3_routes` get_sheet, post_row, post_read, get_doc, post_sign (`G1.http_gate`, "read" for the two reads, "full" for the writes).
8. Agents' context: `i6_chat.chat` (North), `a1_chat.chat` (Span), `f1_chat.chat` (Flow), `c3_chat.chat` (Lumen) call `G1.check_agent`; they refuse a person who may not see the project. The library/K1 gate on files an agent reads is unchanged and now covers project files too (rows carry the team as grants; a Restricted project's rows have `visibility: "project"`).
9. Removed ad-hoc role checks: `p1_project.document` (the analyst/admin/sponsor list) and the Pulse "decision maker / signed" test.
