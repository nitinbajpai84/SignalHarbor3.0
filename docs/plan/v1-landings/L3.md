# L3 The library sorts itself into folders

## What landed
- `sh_platform/v1/l3_library.py`: `classify` (rules over name, note, column names, first heading; reuses K1's rule table and `topics_for` vocabulary), `ensure` (one-time idempotent sort and move, with the unclear rows sent to Jev in a background batch via `k1_classify.ask_topic`; rows show `sorting: true` until it answers), `move` (owner or admin; recorded in `folder_log`), `folders` (counts and items from the C4 listing, so visibility is unchanged), `proposal` ("Goes to: ..." for the upload row). 12 folders: Process maps, Reports and packs, Benchmarks and targets, Policies and rules, Data samples, Statements and invoices, Capital calls and distributions, Emails and notes, Minutes and decisions, External and market, Pictures and scans, Other.
- Each row gets `folder`, `folder_by` (rules | Jev | owner after a move or a changed choice at upload), `subfolder` (a year when the name has one; counterparty is not derived, names are too varied to call it obvious), `sorting`.
- `sh_platform/v1/l3_routes.py` + `l3.permissions.yaml`: `GET /api/v1/library/folders?q=` -> `{folders:[{folder, icon, count, items}], sorting, all}`; `PUT /api/v1/library/{id}/folder` {folder}.
- UI: `ui/src/v1/l3/LibraryFolders.tsx`, `api.ts`; the attach menu's library view is now folders (icon, name, count), search across all, an opened folder lists items (name, note, owner, date, lock state, tick), owner can move an item. The upload row shows "Goes to: X" with a select to change it (`UploadStep.tsx`).

## On disk
- New uploads: `data/<company>/library/<folder>/<name>`; project uploads (G1): `data/<company>/projects/<pid>/files/<folder>/<name>`. A name clash gets the item id in the file name.
- Migration (first read of `/api/v1/library` or `/folders` after deploy): rows with no folder are classified, files moved out of `library/files/` and flat `projects/<pid>/files/`, `path` updated, the old path kept in `was`, and `library/aliases.json` {old: new} written. `CompanyPlane.path` falls back to the alias when a library/projects path no longer exists, so stored old paths (extractions, sow sources, dashboard notes) still open. Second run changes nothing.
- NOT moved: the seeded `documents/*` and `landing/*` items. The scans, loader, X5 and the company page read those folders directly, so they stay and are only shown in a folder. Say so if you want them copied into `library/<folder>/` too (needs the scans pointed at the index first).

## How to test by hand
1. Restart the backend, sign in as Arjun Mehta (neera) or Meredith Shaw (ardmore-1), open any conversation, "Add context for a more relevant conversation" > "From the organisation's library".
2. First open: folders with counts (Policies and rules, Emails and notes, Capital calls and distributions on ardmore-1, ...). Look in `data/<company>/library/` for the folder directories after an upload.
3. Open a folder, tick a file: a chip appears under the chat; nothing was ticked beforehand.
4. Type a word in Search: matches show across folders.
5. Upload a file: the upload row says "Goes to: <folder>" with a select; change it, add; the file lands in that folder's directory. Move one of your own files with the select in the folder list; the file moves on disk.
6. Sign in as another person: your private files are not in their folders or counts; after "Share with the company" they are.
