# Review: K2 The live company map as active knowledge context

Reviewer pass of 8 Oct on `sh_platform/v1/k2_map.py`, `k2_routes.py`, `k2.permissions.yaml`, `ui/src/v1/k2/K2Panel.tsx`, `tests/v1/test_k2.py` and the edits in `m1_map.py`, `m1_routes.py`, `p1_project.py`, `p2_pulse.py`, `ui/src/v1/m1/MapPage.tsx`. L2 files not reviewed (other reviewer).

`SH_MODEL_PROVIDER=off python -m pytest tests/v1 -q`: 175 passed, 2 failed. Neither is K2's: `test_l3::test_unclear_items_go_to_jev_in_a_batch...` dies on a Windows `PermissionError` reading `library/index.json` in the tmp copy (a file-lock flake in C4), and `test_proposal_speed::test_picture_proposal_is_quick` is an OCR timing test (11 s against a 5 s bar under a full-suite run). All 13 K2 tests pass, including the routes test on the demo copy.

## Verdict

**Accept after two fixes.** The access model is right (every read filters through `g1_access.may_see_project`; restricted definitions are absent from concepts, ask, collision, proposals, Pulse and suggestions, and are the team's silhouette on the map), nothing merges without a person, every id in the collision fact is program-filled, accepting a suggestion is an overlay in `graph/k2.json` and never touches `sow.json`, `suggestion` in `QUIET` opens no sign-around, and the touches on `create_project` / `signed` are guarded and cannot fail a write. Two things must change before the orchestrator wires North: K2's own model prompts send people's names untokenised, and the wiring lines in K2.md would break North on exactly the case they serve.

## Blockers

### B1. K2's prompts carry people's names without registering them with the vault (egress rule, D-007)
`sh_platform/v1/k2_map.py:316` (`_diff_line`) sends `"team": _clean(_label(d), 60)` where `_label` (`k2_map.py:304-305`) is `d["team"] or d["project"] or d["owner"]`, and `d["team"]` defaults to the owner's name (`k2_map.py:137`). `_same` (`k2_map.py:238-241`) sends the definitions' free text the same way. Neither path calls `register_names` before `run_agent`, unlike `i6_chat.ask` (`i6_chat.py:512`) which registers the conversation's people first.
Failing scenario: Fiona signs "Net worth" with no `team` field; Pete signs a second one. The next `_sync` with a provider on builds the DIFF prompt `variants: team: Fiona; meaning: ...` and `team: Pete; ...`. If Fiona's name is already in the vault (she chatted with North), the gateway refuses the payload and the line falls back to the stub for good; if she never chatted, her name leaves the machine in clear. The project title (`_label` fallback) and any name typed inside a definition go the same way.
Fix: in `_ask_json`, before `run_agent`, call `sh_platform.build.agents.runtime.register_names(plane, "", names)` with the owners, teams and project titles of the definitions in `ctx` (the labels and the definition text then go out tokenised like North's context). One line plus a list comprehension; the tests can assert the vault holds the owner after a sync with a fake model.

### B2. The North wiring lines in `docs/plan/v1-landings/K2.md` ("Wiring North needs") are not safe to paste
Two faults in the proposed snippet:
1. `ctx["facts"] = [*ctx.get("facts", []), fact["question"]]` appends a string to a list of figure dicts. `ctx["facts"]` is built by `i6_chat._facts` (`i6_chat.py:483-497`, `{"value", ...}` rows sized to `MESSAGE_LIMIT`) and is read by `doc_tools.registry` (`doc_tools.py:29,51`: `f.get("value") for f in self.facts`) and the reply guard. A string in that list raises `AttributeError: 'str' object has no attribute 'get'` on the first document search, and the appended text is not counted in the message budget.
2. `ctx["collision"] = fact` is set **after** `context()` has already run `fit()`. `fact["definitions"]` is a list of two or more dicts whenever there is a collision (that is the whole point: "already has two definitions"), and the egress rows guard refuses "a LIST of two or more objects" (`sh_platform/egress/rows.py:14`). North's call is refused and the fallback reply runs precisely when the collision question should be asked. The landing note's own last sentence ("put the facts ... as a one-line string, already flat") contradicts the snippet.
Also `new_kpis` is undefined in `i6_chat.ask` as it stands, and `viewer` may be `None` there (works, but then every Internal/Restricted definition is filtered as a stranger would see it).
Fix for the note (and for whoever wires it): keep `ctx["facts"]` untouched; add one flat string key built by the program, e.g. `ctx["known_definitions"] = fact["question"] + " " + "; ".join(f"{d['team']}: {d['definition']}" for d in fact["definitions"])` **before** `fit()` inside `context()`, or pass it through `egress_fit.fit` again; register the owners' names with `register_names` first (same as B1); take the KPI names from the current `sow["kpis"]` not an undefined `new_kpis`; and have North's reply carry the person's choice as a program-checked enum that `record_choice` validates (it already refuses anything outside `CHOICES`).

## Should-fix

- **Model never re-consulted after an accepted edit; the difference line degrades to the stub for good.** `_sync` (`k2_map.py:355-356`) builds a model only when a definition is new or a concept has no line yet. `answer_suggestion` → `_change` runs `_sync` *before* `_apply` writes the edit; the next `_sync` sees no new definition, the concept already has a line, so `model=None`, and `_regen_diffs` (`k2_map.py:330-332`) stores `_stub_diff` under the new key with `by: "stub"`, and the key now matches forever. Scenario: step 3 of the demo (accept a change) silently turns the model line "Finance counts private funds at last NAV; Performance excludes them" into "Worded differently: Fiona says ...". Fix: include `any(st["diffs"].get(c, {}).get("key") != _key(ds) for c, ds in _by_assign(...) if len(ds) > 1)` in the model-needed test (the test `test_difference_prompt_has_no_digit_and_regenerates...` passes only because it passes a model explicitly).
- **Model calls run inside graph rebuilds and inside GET requests, uncapped.** `add_nodes` → `_state` → `_sync` may call the fast model once per overlapping concept pair (`_near`) and once per changed concept (`_regen_diffs`). `m1_routes._open` calls `rebuild_if_dirty(wait=True)` on every map and K2 route, so a `GET /api/v1/map/ask` after a sign can block on several provider round trips, and the background rebuild thread (`touch` → `hooks._background`) spends money with no viewer and logs costs under `north/summary` with an empty intent id. Suggest: `add_nodes` and all read paths call `_sync(..., model=None)`; the model is consulted only on the write paths (`sign` through `touch`'s caller, `record_choice`, `answer_suggestion`, `decide_proposal`) with a per-sync cap (say 5 calls), or in a background job keyed on the k2 store.
- **Internal projects' definitions, formulas and `why_different` are shown to non-members.** `_may` (`k2_map.py:386-387`) only hides level `"none"` (Restricted). G1 says a non-member of an Internal project sees title, stage and owner only; M1's G1 clause hides only restricted nodes on the map, so this is consistent with the map but not with the artefact rule. Decide once (Nitin): if the map is the exception, write it in the card; if not, `_may` should hide `"preview"` too and the `"read"` level stays open.
- **"Suggest a change" on a concept 404s when its oldest definition is one the viewer cannot see.** `_target` (`k2_map.py:567-570`) picks `ds[0]` by signed date over all definitions; `suggest` then refuses with "no such thing" (`k2_map.py:587`). Scenario: a Restricted project signs "Net worth" first, an Open one second; an outsider sees the concept with one variant but cannot suggest on it. Pick the oldest *visible* definition's owner.
- **Owner may be a team name, so nobody can answer.** `owner` is the KPI's free-text `owner` (`k2_map.py:134`), e.g. "Finance team"; the suggestion is addressed to that string and `P.answer` requires `c["to"] == viewer.name`, so the suggestion sits open forever and the Pulse card never clears. Address to the project raiser when the owner is not a person (`_Map.who`'s person test, or `K.directory`), as `_node_owner_def` already does.
- **Per-call cost grows as sows × projects × comments.** `_raw_defs` calls `P.for_intent` per sow (each scans every project file), `_may` calls `may_see_project` per definition per call (`P.read` + `P.comments` for a non-member), `_groups` rebuilds the `EntitlementStore` and reloads the pack on every sync and every `collision_fact`, and `suggest` runs `_sync` twice (`_state` then `_change`). Fine for the demo; memoise `for_intent`/`may_see_project` per call and load `_groups` once per sync before the company has a few hundred KPIs.
- **Reopened intents of work.** `_raw_defs` (`k2_map.py:124`) treats any sow with a `signatures` history as signed and reads its *current* `kpis`. If a reopen leaves `signatures` in place while North edits the draft (C2's history ruling in `i4_sow.sign`), draft text shows as the company's meaning until the next sign. Read the last signed version's text when the record keeps one, or require `state == "signed"`.
- **`POST /api/v1/map/choice` with an empty or foreign `iid`.** `G1.for_intent(plane, viewer, "", "full")` returns `"full"` (no project), so the choice is stored under `choices[""]`. Validate `iid` with `P._IID` and cap `kpi` (`k2_routes.py:67-69`, `k2_map.py:453`).

## Nits

- `answer_suggestion` (`k2_map.py:645-650`): `P.answer` marks the comment answered before `_apply`; if `_apply` raises (e.g. a concept merged away since the suggestion), the comment is answered, the store is not saved, and the suggestion stays open. Apply first, answer the comment last.
- `decide_proposal` lets the owner of either side merge the other team's concept; the card allows it, but nothing tells the other side afterwards. A Pulse "Worth a look" line for the other concept's owners would close that.
- `_merge` keeps the folded concept in `st["concepts"]`; `_apply`'s `rename` on a stale `s["concept"]` edits a dead concept. Resolve with `_live` in `_apply` as elsewhere.
- `create_project` is also called from `project_of` on reads, so a first read of an old intent now triggers a map rebuild; harmless (dirty flag coalesces), worth a comment.
- `k2_routes.py:68`: the one-line `_run(lambda: G1.for_intent(...))` discards its result; a plain `_run(...)` call reads oddly. House style: no `;`-joined imports in the landing note's snippet.
- `K2Panel.tsx`: `Proposals` fetches on mount for every node page; fine for now, but the list is per company, not per node, so it could live once in `MapPage`.
- Permissions yaml lists every role on every K2 route and leaves the decision to the handlers; that is the K1 pattern, fine, but say so in one comment per write route.

## What was checked and is sound

- Visibility: `concepts`, `answer` (ask), `collision_fact`, `proposals`, `pulse_items`, `suggest` all filter with `_may` → `G1.may_see_project`; the difference line is shown only when every variant is visible, else a stub from the visible ones; restricted definition nodes get `restricted_to` via `G1.restrict_nodes`; a concept drawn only from restricted projects is not drawn; `m1_routes.get_ask` searches the viewer's gated graph. Test `test_a_restricted_projects_definitions_are_the_teams_only` covers it.
- No silent merge: same normalised name = variants (by design); pack synonyms and word overlap only ever `_propose`; `_merge` runs only from `decide_proposal` (owner or admin) or an accepted `merge` suggestion; declines are remembered in `nope`.
- Model output entering storage: only a bool (`_same`) and a digit-stripped sentence (`_diff_line`); no ids, no figures; the collision fact and its question are program-built with the count spelled out.
- Signed content untouched: edits are an overlay in `graph/k2.json`; `_write_on_kpi` writes only to a draft (`state != "signed"`) and only the choice fields.
- `suggestion` in `QUIET`: `sign_block` and `p5_handover.go_live` both skip QUIET kinds, and `p1_routes` does not accept `kind` from the body, so nobody can post a blocking comment as a suggestion or a suggestion as a blocker.
- `touch` on `create_project` / `signed`: wrapped in `suppress(Exception)` and `touch` itself never raises; `test_project_creation_and_signing_land_on_the_map` covers both.
- Industry: synonyms come from the company's pack through `PackLoader`; no KPI names or industry words in code.
- Stub when off: `build_model_client` returns `None` for `SH_MODEL_PROVIDER=off`, `_ask_json` returns `None`, the rules propose and `_stub_diff` stands in with `by: "stub"`.
