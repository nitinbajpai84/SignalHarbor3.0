# Review: READ, PERF-UPLOAD, L3 (8 Oct)

Summary: READ is sound (every tool call re-derives the readable ticked set; results are capped strings; the index is filtered by path, never trusted for access). PERF-UPLOAD keeps the personal-data rule but the 3-proposal cap and the 8 s pool are leaky. L3 is a blocker: name-based disk paths plus the alias fallback let a stored path (sow source, thread turn) open a *different, later* upload, possibly another person's private file; and "move back" or an interrupted migration renames files with an id tag.

Checked: `SH_MODEL_PROVIDER=off python -m pytest tests/v1 -q` 149 passed (159 s); `cd ui && npx tsc --noEmit -p .` clean. Probe script (alias loop, move-back, interrupted-migration replay) run by hand; results below.

## Blockers

1. L3, `sh_platform/v1/l3_library.py:163-172` (`rel_path`) with `catalogue_scan.py:51-66` (`_files`), `i2_north.py:157` (`file_preview`), `plane.py:70-74`.
   Scenario: Ann uploads `x.md` (shared) -> `library/Reports and packs/x.md`; it is ticked in an intent, so `sow.sources[].sample_path` and `thread.turns[].files[].path` record that path. Ann deletes it. Bob uploads a *private* `x.md` that the rules (or his choice) put in Reports: same disk path, no clash (the old file is gone). The catalogue scan of Ann's intent (`_files` reads every stored path, no row check) and `file_preview` now read Bob's private file into Ann's North context. Before L3 every stored path was `library/files/<id>__name`, so a stale path could never point at another upload. The alias widens it: a stale alias whose target was deleted makes a new upload at the old name land on the alias target (`c4_library.py:179` `plane.path(*item["path"])` follows the alias before `write_bytes`), so the disk and the index disagree.
   Smallest fix: keep the id in the on-disk name, `f"{_base(item)}/{folder}/{item['id']}__{name}"`; drop the clash branch. Stored paths are unique again; aliases keep working for the migrated rows.

2. L3, `l3_library.py:167-171` and `:183`: the clash test and the move destination go through `plane.path`, which follows the alias.
   Probe: upload `x.md` to Other, move to Reports, move back to Other -> the file is renamed `x-abcdef.md` on disk and `aliases.json` holds two entries pointing at it (the old Other path "exists" through its own alias). Same for an interrupted migration: the file was moved and the alias written, the index not yet; the rerun sees the target "taken" and renames it `y-zzzzzz.md`. Nothing is lost or duplicated, but every move back, and every restart during the first `/api/v1/library` after deploy (the migration reads each file, including OCR of pictures, before the one index write at `:247`), renames files. Fix 1 removes the clash; otherwise use `plane.root.joinpath(*rel.split("/"))` for the existence check and the destination, and in `_record_move` add `m.pop(new, None)` (a path that exists again must not alias; without it `{A: A}` after fix 1 recurses in `plane.path` as a `RecursionError`, which `path` does not catch).

## Should fix

3. PERF-UPLOAD, `k1_routes.py:26,50` vs `c4_library.py:176` -> `k1_access.py:284` -> `C.propose`. The upload itself runs the same read and OCR outside `_heavy`; `POST /api/v1/library` bypasses the 3-concurrent cap, and the UI's proposal-then-upload pays the OCR twice on different threads (`_reads` is thread-local; `ocr_local._read` caches 4 pictures only). Fix: move the semaphore into `k1_classify.propose` (`with _heavy:` around the body) and delete it from the route.
4. PERF-UPLOAD, `k1_classify.py:276-284`: a late `ask_topic` keeps running after the 8 s wait, and the queue is unbounded; three slow calls fill the pool and every later proposal waits 8 s for a future that is still queued, then returns the rules' answer while the stale calls still spend model budget. Fix: `fut = _topic_pool.submit(...)`; on timeout `fut.cancel()`. Request threads are not blocked beyond 8 s (checked), so this is cost, not a hang.
5. READ, `g3_routes.py:41` (`_item`): a chip or sheet doc link holds the path at the time of the reply; after an L3 move the string compare finds no row and the viewer gets 404 "not in the company's files". Fix: also match `i.get("was") == rel`, or resolve `rel` through `l3_library.alias` before comparing. (Access stays row-based, so no leak either way.)
6. L3, `l3_library.py:116-118, 241`: the migration runs in the first `GET /library` request thread and calls `C.outline` on every unsorted row, which OCRs every picture and up to 5 pages of each scanned PDF (4 s budget each). A library with 50 pictures stalls the first list for minutes and holds the index lock. Fix: pass `head_text`/`columns` only for text and table files (`ext in _TABLE or ext in text types`), skip the read for pictures and PDFs (the name already sends pictures to "Pictures and scans").
7. READ, `doc_index.py:116-117`: `search` indexes every ticked file inline with the reply, with the reader defaults (20 OCR pages, no time budget) and outside `_heavy`. The first question after ticking a scanned PDF takes North's reply past the model timeout. Fix: `ensure` with `ocr_pages=PROPOSAL_OCR_PAGES, ocr_seconds=...` for the first pass, or index at upload in the background (the READ note already names this).

## Notes

8. READ egress: tool results cross the gateway as `role: tool` text (`egress/model.py:86-88`) and the vault tokenises names; `_summary_only` refuses lists over 50 and the results are at most 8 passages of 1,200 characters or 60 lines/3,000 characters. Nothing returns a whole file; `/benchmarks/sheet/doc` (up to 3,000 lines) is a person's view behind `_item` (visible and readable), not an agent's.
9. READ access: `_files` is rebuilt on every call from `c4_library.selected` (visible and `K.can_read`) plus `can_read_intent`; a tick removed, a grant revoked, a file deleted or a row made private mid-reply drops out of the next call. The FTS index keeps passages of deleted or revoked files, but every query is `path in (<readable ticked paths>)`, so they are unreachable; a re-upload at the same path re-indexes on size or mtime. Alias values are plane-relative and re-validated by `path()`, so an alias cannot leave the plane or reach another company; only the server writes `aliases.json`.
10. Personal-data rule under the speed-up holds: an empty OCR result, a PDF with no readable text, a page budget or time budget left unused all raise or set `partial`, and `_unread` makes the file Restricted (`k1_classify.py:125-136, 297-298`). Pre-existing gaps, not new: a PDF whose first page has a text layer and whose other pages are scans is never OCR'd (`reader.py:186`), and `scan_pii` reads 3,000 lines / 2,000 rows only.
11. `k1_classify._reads` keeps the last proposal's text in each worker thread for the life of the process. Clear it at the end of `propose` (`_reads.key = None; _reads.got = None`).
12. `doc_tools._files` keys by lower-case name: two ticked files with the same name make the second unreadable by `read_document` and absent from search. Key by `f"{name} ({id})"` or fall back to the path.
13. Thread turns carry `sources` (file name, lines) for everyone who may open the conversation; a reader who may not open the file sees its name and the quoted reply. This is the reply's own content and the chip 403s on click; the same as before READ.
14. Tests: `test_picture_proposal_is_quick` can never call the model (a picture is "Pictures" by extension), so `Stub.calls == 0` proves nothing; `test_pages_left_unread_keep_the_file_restricted` has no twin asserting a fully read scan is *not* restricted, so an always-Restricted bug would pass. `test_l3` covers the one-time migration and a single move but not move-back, not the stale-path reuse above, and not an interrupted run; add the probe cases (move to a folder and back: path and disk name unchanged; delete then re-upload the same name: the old sow path no longer opens anything).

## Verdicts

- READ: pass. Ship with 5 and 7 on the list.
- PERF-UPLOAD: pass after 3 (the cap is the landing's promise) and 4.
- L3: blocked by 1 and 2. The id-in-name fix is one line in `rel_path`, re-run the migration tests and the probe, then it passes.

## Fixes

- B1 (`l3_library.rel_path`): the on-disk name is `<folder>/<id>__<name>`, the clash branch is gone, so a stored path is unique to one upload. `c4_library.path_ok` (new) lets `catalogue_scan._files` and `i2_north.file_preview` read a library path only while an index row owns it (and, where a viewer is known, may read it). Test: `test_a_stale_path_never_opens_a_later_upload`.
- B2: `_place` moves with `_raw` (no alias following) and only when the destination is free; if the source is gone and the destination is there (interrupted run) it just takes the new path; `_record_move` pops the new path (no self-alias). Tests: `test_move_back_keeps_the_path_and_the_disk_name`, `test_an_interrupted_migration_is_not_renamed_on_the_rerun`.
- S1: the 3-concurrent cap now lives in `k1_classify.propose` (route and upload share it). S2: `_topic_in_time` cancels a queued call on timeout (pool stays 3 workers). Also item 11: `_reads` is cleared at the end of `propose`.
- S3: `g3_routes._item` also resolves the path through `l3_library.alias`, so a chip made before a move still opens (access stays row-based).
- S4: the first sort (request thread) no longer reads pictures or PDFs (`_shape(..., ocr=False)`); their text is read only in the background batch.
- S5: `doc_index` indexes pictures and PDFs in a 2-worker background pool (`index_later`, started at upload and at the first search); `search_documents` / `read_document` return `still_reading: still reading <file>` until done. `ensure` no longer holds the database lock while reading a file. Test: `test_a_scan_is_read_in_the_background_and_search_says_still_reading`.
- Tests: `test_picture_proposal_is_quick` now has a control (`test_the_model_is_reachable_when_the_rules_do_not_know`) and an unreadable picture name; twin `test_a_fully_read_scan_is_not_kept_restricted`.
- Leftover (seeded `documents/*` and `landing/*` into the folder layout): NOT done. catalogue_scan (`_landing_sources` lists `landing/` by directory), the b4 loader (stages `_b4_*` beside the files), x5_extract (`_doc_path` is under `documents/`), b2 scan, file_context and doc_index all read those two folders by path, so moving them needs every reader switched to the index at once; left in place rather than half-moved.
- Not changed: item 12 (`doc_tools._files` keyed by lower-case name) and the PDF mixed text/scan gap in item 10.

Closed:
- B1 closed. `l3_library.py:167-170` puts the row id in every on-disk name, `c4_library.py:186` and `:209` stamp it at upload, so no later upload can land on a stored path (ids are `lib_<12 hex>`, random).
