## What to pin (proposed `ACTS` lines for tests/auth/test_role_matrix.py; the orchestrator edits it)
Today every v1 route falls to "company_admin may, others unchecked", so a widened yaml would pass silently. Pin them to the seats:
```python
DM, BUILDERS = {"company_admin", "sponsor"}, {"company_admin", "analyst"}
V1 = "/api/v1"
ACTS.update({f"POST {V1}{p}": DM for p in ("/intents", "/intents/{iid}/thread", "/intents/{iid}/thread/files",
    "/intents/{iid}/sow/sign", "/intents/{iid}/sow/send-back", "/build/{iid}/scan/agree", "/build/{iid}/scan/send-back",
    "/consume/offers/{offer_id}/have", "/company/documents")})
ACTS.update({f"PUT {V1}/company": DM, f"PUT {V1}/intents/{{iid}}/sow": DM})
ACTS.update({f"POST {V1}{p}": BUILDERS for p in ("/build/{iid}/design", "/build/{iid}/scan", "/build/{iid}/mapping",
    "/build/{iid}/load", "/ops/loaded")})
ACTS.update({f"PUT {V1}/build/{{iid}}/mapping/rows/{{n}}": BUILDERS, f"GET {V1}/ops": BUILDERS})
ACTS.update({f"GET {V1}{p}": SIX for p in ("/home", "/consume", "/consume/{iid}/{code}", "/consume/offers",
    "/intents/{iid}/sow", "/intents/{iid}/sow/download", "/intents/{iid}/room", "/build/{iid}/design", "/build/{iid}/scan")})
ACTS.update({f"GET {V1}{p}": DM | BUILDERS for p in ("/company", "/intents/{iid}/thread", "/build/{iid}/mapping",
    "/build/{iid}/mapping.xlsx", "/build/{iid}/runs")})
ACTS[f"POST {V1}/intents/{{iid}}/room"] = DM | BUILDERS
```
(`SIX` is already defined in the matrix. Caveat: the matrix counts any 403 with `error: "forbidden"` as a guard refusal, so B1's and I1's handler refusals below would read as denials for the right role too; fixing those two codes avoids a false failure.)
