# E0b1 Data agent skill

Merged `skills/span/` and `skills/flow/` into `skills/data/` with v2 rules: three times on every fact (effective, received, recorded); never overwrite, a correction supersedes; estimates apart from official NAV; identifier aliases only after approval; control totals required for load acceptance; model changes proposed to head of data.

## Files

- `skills/data/playbook.md` (1264 chars) — unified data agent playbook: intake, cleaning, estimates, aliases, control totals, model governance.
- `skills/data/questions.md` (594 chars) — six questions for the head of data on policy decisions.
- `skills/data/traps.md` (829 chars) — nine key risks and guardrails from v2 rules and spreadsheet patterns.
- `skills/data/examples.md` (1652 chars) — three worked mappings from messy sheet headers to DBML tables (position_snapshots, valuation_observations, cash_movements) with transforms (thousands, day-first dates).
- `tests/v1/test_e0b1.py` (5 tests) — loads skill through `skill_loader.load_skill("data")`, checks key v2 rules are present, verifies size under 6000 character cap, confirms all four files exist.

**Total skill size: 4342 characters (under 6000 limit).**

## Expected

- 5 tests pass (loads, size, rules, mappings, file existence).
- Skill text includes all six v2 rules in plain words.
- Three worked examples: position_snapshots, valuation_observations, cash_movements.
- No config or code in the skill; policy and examples only.

## Known limits

- Skill loaded as a text block (playbook + questions + traps + examples, concatenated). Company-level overrides via `data/<company>/skills/data/` (if they exist, win; existing skill_loader pattern).
- Worked examples show transforms (thousands multiply, date parsing); actual implementation of profile_sheet and propose_mapping is in E0b2 tools.
- Warehouse location and access checks (E1d) are separate; skill text has no secrets or queries.

## Wiring for the orchestrator

- The data agent registered in the tool registry calls `load_skill("data")` on startup. No new wiring needed; skill_loader is existing.
- Company admin edits skills/data/ overrides on the Admin skills page (existing pattern from consumer, north, flow agents).
- Landing note: E0b1 is the playbook skill only. E0b2 tools (profile_sheet, propose_mapping) and E0b routes (mapping CRUD) are separate cards. This card owns the knowledge rules; E0b2 enforces them in code.
