# E0b2 Data agent tools and mapping records

## What changed
- `e0b_tools`: `profile_sheet` (openpyxl, local only: header row incl. merged bands, data range, totals row, units, text-date day/month order, in-progress flag, purpose guess), `propose_mapping` (synonym rules per sheet purpose, then the model for leftovers, every target checked with `e0a_catalogue.has_field`, invented targets dropped to `ignore` and named in `rejected`), `similar_approved_mappings`, `propose_model_change` (opens an E0a proposal), `registry(...)` (the data agent's tools: list_tables, describe_table, profile_sheet, similar_approved_mappings, plus propose_mapping and propose_model_change as propose-only tools).
- `e0b_mappings`: records in `data/<company>/model/mappings/<id>.json`; `get_approved`, `save_proposal`, `approve`, `reject`, `listing`, `get`. A layout change on the same file pattern and sheet saves as the next version (`layout_change: true`); approving it retires the earlier approved version.
- `e0b_routes`: list, get, approve, reject under `/api/v1/model/mappings`.
- Shapes are compatible with `tools/eval_data_agent.py` as documented; the runner was not changed.

## Files
`sh_platform/v1/e0b_tools.py`, `e0b_mappings.py`, `e0b_routes.py`, `e0b.permissions.yaml`, `tests/v1/test_e0b2.py` (12 tests), this note.

## Test on the demo
1. `SH_MODEL_PROVIDER=off python -m pytest tests/v1/test_e0b2.py -q`
2. Evaluation set: `python tools/eval_data_agent.py <company>` (the company must exist; set `SH_DATA_ROOT` for a tmp root). Result: mapping 100% in every trap, 0 invented targets, 3/3 in-progress, 1/1 totals mismatch caught.
3. In Python: `p = profile_sheet(path); r = propose_mapping(plane, p); mid = e0b_mappings.save_proposal(plane, r["mapping"])`, then `GET /api/v1/model/mappings?state=proposed` and `POST .../{id}/approve` as a data engineer other than the proposer.

## Contract notes
- `propose_mapping(plane, profile, viewer=None, model=None)`: extra optional `model` (callers pass `get_model(state, plane)`; None or `SH_MODEL_PROVIDER=off` means rules only and the note says so). `plane` may be a plane or a company slug (the runner passes a slug; resolved from `SH_DATA_ROOT`, default `./data`).
- Return also carries `mapping` (the record `save_proposal` takes: file_name, sheet, header_row, purpose, columns [{source, target_table, target_field, transform}], proposed_by) and `rejected`. `propose_mapping` does not save; E0c2 calls `save_proposal` (for a layout change) with `proposed_by` of the agent.
- `profile_sheet` also returns `file_name`, `column_info` (kind, date_format per column), `totals` {row, stated, sums, matches}, `totals_match`, `exclude_rows`, `first_data_row`, `last_data_row`, `row_count`, `layout` via the mapping's `layout`. The table ends at the first blank row; notes below it are ignored.
- `get_approved(plane, file_name, sheet)` matches the file name against the record's pattern (digit runs become `*`, so `pos_2026_08_x.xlsx` and `pos_2026_09_x.xlsx` share a mapping) and the sheet name. E0c2 compares the new file's columns with the record's `layout` to detect a layout change.
- Approve and reject: data_engineer seat, or the record's `owner` (set by E0c1 when saving the proposal, as a display name); never the proposer when `proposed_by.kind == "person"`. `reject` needs a reason.

## Known limits
- Synonyms cover the six sheet kinds of the evaluation set; unknown headers are `ignore` until the model or a person places them. A text date sheet with only days up to 12 is read as day first.
- Model path (`_model_targets`) is stubbed in tests, never run live here.
- The sheet `owner` is a name string; if E0c1 stores owners by account id, change `_who_may_decide` in one place.

## Wiring for the orchestrator
- Router auto-installs (`e0b_routes.router`, `e0b.permissions.yaml`).
- Register the tools for the data agent where the agent runs: `e0b_tools.registry(gate, module_id, plane, viewer, model)` (merge with the document tools registry as needed).
- No new packages.
