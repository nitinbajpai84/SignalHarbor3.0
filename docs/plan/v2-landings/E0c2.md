# E0c2 Load engine with control totals

## What changed
`e0c_load.load(plane, file_id, viewer) -> dict` loads a landed spreadsheet into the warehouse only when it adds up.
Flow: read the file record (E0c1) and its profile (E0b2); find the approved mapping; read the sheet by the mapping's header row; parse and convert every row (thousands, day-first text dates); compare row count and every total the sheet states against what the rows add up to; only then write.

Written: `source_batches` (one per file and sheet, reference = hash prefix + sheet), `batch_control_totals`, `source_records` (sheet, row number, cell range like `A5:G5`, `recorded_at`, content hash, `raw_payload_uri` = the original file URI), then the observation rows through `e1_write.record_many` (one transaction). A later file for the same subject supersedes the earlier row (link passed to the writer).

Result `status`: `loaded`, `waiting_for_mapping` (with `reason` `no_mapping` or `layout_changed`, and `proposal_id`), `rejected_totals` (message names the measure and both figures; the batch and its totals are kept, no source records, no observation rows), `quarantined` (sheet marked In Progress, unreadable cell, or the write failed), `already_loaded`. Also `held_back` (row and reason: fund or portfolio not approved), `control_totals`, `batch_id`, `mapping_id`, `mapping_version`.

Files: `sh_platform/v1/e0c_load.py`, `tests/v1/test_e0c2.py`, this note.

## Rules I chose (please confirm)
- A sheet the profile marks In Progress is not loaded (quarantined).
- Defaults where the sheet has no column: positions `view_type` operational, `data_status` official (final sheet) or estimated; valuations `valuation_type` manager_estimate, `approval_status` unapproved; cash `confirmation_status` noticed; NAV `nav_status` approved_official (final) or draft; market `observation_type` index_level.
- Instruments load only when `e2_match.resolve` says approved for this file's source system (source_code of the file, created as a `spreadsheet` source system if missing); proposed or unknown rows are held back, the rest loads.
- Tables handled: position_snapshots, valuation_observations, cash_movements, nav_snapshots, market_observations. Not transactions.
- Layout change = the set of file headers differs from the mapping's source columns (case-insensitive).

## Wiring for the orchestrator
- E0c1 `_LOAD_STATES` maps only loaded, waiting_for_mapping, rejected_totals, layout_changed. Add `quarantined -> quarantined` and `already_loaded -> loaded` (this card does not own that file).
- No new packages.

## Known limits
- One sheet per file (the profile's sheet). Capital calls go to cash_movements as the E0d expectations say.
- Totals checked on the file as a whole, including rows later held back.
- If observation writing fails after the batch rows are written, the batch is marked quarantined (the writer's transaction leaves no observation rows).
