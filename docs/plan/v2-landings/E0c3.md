# E0c3 · Data intake screen

## What changed
Screen `/centre/data/intake` (title "Data intake"): files grouped by source with state words, owner, received and last load, an upload control and the note "Drop files in the inbox folder or upload here". File page `/centre/data/intake/:fileId`: profile summary, mapping column by column with Accept / Not this (shown only when the server says `can_decide`), control totals table, load result with held-back names, and Read / Load buttons when `can_act`.

## Files
`ui/src/v1/e0c/` : `api.ts`, `routes.tsx`, `IntakePage.tsx`, `FilePage.tsx`, `e0c.test.tsx` (3 tests).

## How to test on the demo
1. Open `/centre/data/intake` as Operations (Mei); files appear grouped by source.
2. Open a file waiting for mapping; check the mapping table and totals.
3. As the sheet owner or data engineer, press Accept (or Not this with a reason).
4. Press "Load this file"; read the result and control totals.

## Routes assumed (E0c1 and E0b2 had not landed; adjust `api.ts` in one place)
- `GET /api/v1/intake/files` -> `{files:[{id,name,source_code,source_label?,state,owner,received_at,last_load_at}], can_upload?}`
- `POST /api/v1/intake/upload` (multipart field `file`) -> the file row
- `GET /api/v1/intake/files/{id}` -> file row plus `profile{sheet,header_row,columns[{name}],units,date_format}`, `mapping{id,version,state,can_decide,columns[{source_column,target_table,target_field,transform}]}`, `control_totals[{measure,in_file,loaded,passed}]`, `load_result{state,message,held_back[]}`, `can_act`
- `POST /api/v1/intake/files/{id}/profile` -> file detail; `POST /api/v1/intake/files/{id}/load` -> load result
- `POST /api/v1/model/mappings/{id}/approve`; `POST /api/v1/model/mappings/{id}/reject` body `{reason}`

## Known limits
- Upload posts multipart straight with `fetch` in `api.ts` (the shared client only sends JSON); same CSRF header.
- Mapping edits are not offered, only Accept or Not this.
