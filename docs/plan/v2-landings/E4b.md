# E4b Investigation agent

**Changed**: `sh_platform/v1/e4_investigate.py` (`propose_explanation(plane, exception_id, viewer) -> event id`), `skills/investigation/` (4 files, about 2.3k characters), `tests/v1/test_e4b.py` (7 tests).

**How it works**: access gate via `e4_cases.get`; evidence from exceptions, exception_impacts (with report name and issue date), the two latest valuations of the case's instrument via `e1_asof.chain`, their documents and extracted fields, and event source references. The program computes the bridge (value used before, value now, difference). The model (through the router, names registered, context free of digits) writes only sentences with placeholders such as `{new_value}`; the program fills them. Wording with a digit or an unknown placeholder is dropped for the rules-only text, which also runs when the model is off and says so in the note. The result is written with `e4_cases.add_event(..., "explanation_proposed", note, agent_run_id=...)` inside `e6_trace.agent_run(...)`.

**Test on the demo** (after E4a, E1a, E6a land): 1. seed Evergreen (E0e) and load the amended Fund A statement so the case opens. 2. Open the case and press "Ask the agent to explain" (or call `propose_explanation`). 3. The history shows an "explanation_proposed" entry with the bridge (10,000,000 USD to 10,180,000 USD, difference 180,000 USD) and a Sources line. 4. With `SH_MODEL_PROVIDER=off` the entry ends "Worded by rules only".

**Known limits**: sources are listed in the event note, because `add_event`'s columns for `source_record_id` and `evidence_document_id` are not in the contract; E4a could take them as optional arguments. The bridge covers valuation revisions and report impacts; break and reconciliation inputs (E3b) are not read yet. Warehouse reads do not filter by organization_id (the DDL types it as UUID while `plane.company_id` is a name); access is the `e4_cases.get` gate.

**Wiring for the orchestrator**: E4c's "Ask the agent to explain" button should call `propose_explanation`; a route `POST /api/v1/cases/{id}/explain` is not added by this card (E4a owns the routes). Needs E4a (`get`, `add_event`), E1a (`chain`), E6a (`agent_run`) to be present; each missing module raises after a logged warning. No new packages. The agent's `module_id` string "m4_action" is used for run_agent entitlement checks; confirm it is enabled for companies.
