# B1 landing: Build centre screens

Files: `ui/src/v1/b6/` (api.ts, routes.tsx, ProjectsPage.tsx, BuildPage.tsx, Steps.tsx, b6.test.tsx).
Routes: `/centre/build`, `/centre/build/p/:projectId` (auto-mounted by `v1/index.tsx`).
Test: `cd ui && npx tsc --noEmit -p . && npx vitest run src/v1/b6/` (4 tests pass, no tsc errors in b6).

Assumed response shapes (B2/B4 must serve these or change `b6/api.ts`):
- `GET /api/v1/build/projects` -> `{projects:[{id,title,owner,stage:intent|build|live,plan_state|null}]}`
- `GET .../plan` -> fact-5 record plus `model_diff:{tables_added:[{table,columns}],columns_added:[{table,column,type}]}`, per-table `is_new`, and `can:{approve,reject,run_sandbox,go_live,schedule}` decided by the server (head of data, never the proposer). Source files may be strings or `{name,state}`.
- `GET .../runs` -> `{runs:[{run_id,plan_version,started,finished,status,mode,steps}]}`; `POST .../run?mode=`; `PUT .../schedule` (body = schedule); `GET .../airflow` (download).
- NOT in the card's route list but needed: `GET/POST /api/v1/build/p/{pid}/chat` -> `{turns:[{id,by:"span"|"person",name,text,at}]}`, POST body `{text}`.
