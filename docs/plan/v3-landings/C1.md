# C1 landing: Lumen and dashboards

Files: `sh_platform/v1/cx_dash.py`, `cx_lumen.py`, `cx_routes.py` (auto-included by the `*_routes.py` glob), `cx.permissions.yaml`, `tests/v1/test_cx.py` (16 pass).

Routes (all under `/api/v1/consume/p/{pid}`): `GET /tables`; `GET|POST /dashboards`; `GET /dashboards/{did}`; `POST .../ask` {text, reading?, no_client_figures?} -> {reply, proposals}; `POST .../tiles/{tid}/accept|reject`; `GET .../tiles/{tid}/data` -> {tile, spec, columns, rows, capped, data_used:{tables,last_refresh}}; `GET .../tiles/{tid}/why`; `GET|PUT .../audience` {audience:[user or group ids], refresh?}.

Spec conventions for C2: line/bar/area/point = Vega-Lite marks with `encoding`; KPI number = `mark text` with `encoding.text`; table = `mark text` with `usermeta.view == "table"` (render rows as a table). No `data` in any spec; inject `rows` as `data.values`.

Wiring for the orchestrator: none required. C3 may call `cx_dash.get/list_for` and read `audience`. B4 should append `runs.jsonl` lines with `status` ok|done|success|live and `finished`; `data_used.last_refresh` reads the latest.

Open points: picture upload and local OCR are not here; the route takes the local reading as `reading` and records the "no client figures" tick (the image is never sent by C1). "Why" is worded by fixed rules (model wording not used). Audience access is "some E1d reach" (a user or group with a read/full scope), not per gold row.
