# Review: Consume + demo (C1, C2, C3, X1) · 9 Oct 2026

**Verdict: not ready. Each card passes its own tests (23 pytest, tsc clean, 4 vitest) but the four do not fit together: the screen calls routes that do not exist, the demo dashboard cannot be opened by C1, and the demo's own ask ("net worth by entity") gets "I could not match that".** One fix round of about ten small edits, listed below, makes the journey work.

Driven for real with `.sh-tmp/review_consume.py` on a temporary data root (`seed_evergreen` + `seed_v3_demo`, then C1/C3/A2 functions, model off).

## Blockers (file:line · scenario · fix)

1. **X1 ↔ C1 ids.** `tools/seed_v3_demo.py:269-270` writes `dash-monthly-report` and tiles `t1..t3`; `cx_dash.py:29-30` only accepts `dash-<8 hex>` / `t-<6 hex>`. Every C1 route on the demo dashboard is 404. Fix: seed uses `"dash-" + "00000001"`-style hex (e.g. `dash-0ad2b1c7`) and `t-000001..t-000003`; update `tests/v1/test_x1.py:565`.
2. **X1 ↔ C1 people.** `seed_v3_demo.py:271` `created_by=ENGINEER` (display name) and `audience=[ids[CIO], ids[FINANCE]]` (account ids). C1 compares `created_by` with `viewer.account_id` (`cx_dash.py:40-41, 236, 295`) and audience with `users.id` (`cx_dash.py:246, 306`); C3 resolves audience by `users.id` only (`cx_share.py:700`). Nobody but the admin can open or edit the demo dashboard, and C3 makes no cards. Fix: in `dashboard()` set `created_by=ids[ENGINEER]` and audience to the warehouse `users.id` of the CIO and Finance (`select id from users where display_name = ?`).
3. **X1 ↔ D1/C1 catalogue.** Seed never calls `cat.register_gold`; `cx_dash._gold_names` (`:58-60`) returns nothing, so `/tables` is empty and every tile (seeded or new) is refused "can only read this project's gold tables". Fix: after `build()` in `seed()`, two lines: `cat.register_gold(plane, pid, SLUG, "holdings_monthly", cols)` and `…"cash_daily"…` (idempotent per `_register`), plus `register_bronze` for the two bronze tables.
4. **C2 ↔ C1 paths.** `ui/src/v1/cxui/api.ts:25-27` build `/p/{pid}/tiles/{tid}/…` without `/dashboards/{did}`; C1 mounts `DASH + "/tiles/{tid}/…"` (`cx_routes.py:600, 639-656`). Accept, Not this and every tile's numbers are 404. Fix: `decide(pid, did, tid, how)` and `tileData(pid, did, tid)` with the segment; `TileCard` takes `did` (the dashboard id is at hand in both callers).
5. **C2 ↔ C1 shapes.** `api.ts:14` `Ask = {reply, dashboard}`; C1 returns `{reply, proposals}` (`cx_lumen.py:530`). `ProjectPage.tsx:115` `setBoard(r.dashboard)` sets `undefined`, so the proposed tile never appears and the next message creates a new dashboard (`:111`). `api.ts:26` `decide` expects a Dashboard; C1 returns the tile. `api.ts:29` `share` is `POST` and expects a Dashboard; C1 is `PUT` returning `{audience, refresh}`. `api.ts:12` `TileData = {spec, rows, table, refreshed}`; C1 returns `{tile, spec, columns, rows, capped, row_cap, data_used:{tables, last_refresh}}`, so "Data used: undefined, not refreshed yet". `listDashboards` expects `Dashboard[]` with a `tiles` array; C1 returns summaries with `tiles: <count>` (`cx_dash.py:224`), so `ProjectList.tsx:292` `d.tiles.filter` and `ProjectPage.tsx:100` (`all[0]` as the board) throw. Fix (UI side, smallest): after `ask`/`decide`/`share` call `getDashboard(pid, id)` and set that; `TileData` → `{spec, rows, data_used:{tables, last_refresh}}` and show `data_used.tables.join(", ")`; `listDashboards` typed as a summary `{id, title, tiles: number, accepted: number}`.
6. **Read-only view route.** `api.ts:22` `GET /api/v1/consume/dashboards/{id}`; C1 has no pid-less route. Fix in C1: `@router.get("/api/v1/consume/dashboards/{did}")` that globs `plane.path("consume").glob(f"*/dashboards/{did}.json")` to find the project id, then `D.get` (its `may_view` already does the access check); add the line to `cx.permissions.yaml` with the read roles.
7. **The demo ask does not match.** `cx_lumen._pick_table` (`:405-414`) matches column words only; the demo KPI K01 "Net worth by entity" lives in column `value_usd`. Fix (X1, three lines): name the holdings columns `net_worth_usd` / `net_worth_sgd` in `HOLDINGS_SQL`, `_plan` columns and the tile SQL; update `test_x1.py:554-557`. (Alternative in C1: also score a column by the SOW KPI whose `name` words the text uses, mapping KPI → the gold column named in its formula; larger.)
8. **Trail for the audience.** `a5_trail.py:370-372` (card A2): `me` is `{account_id, name}` but `audience` holds `users.id`. Fix: add `e1_access.user_id_of(con, viewer)` to `me` (one line); C1 cannot change this file. Until then only the maker, analysts and admin can open "Where is this from?" on a tile.
9. **C3 never called.** `cx_routes.py:664-667` saves the audience and stops; C3's note asks for `cx_share.notify(plane, pid, did, "shared")`. Fix: one line after `set_audience` in `put_audience` (inside `suppress(Exception)` with a log, so a card failure never undoes a share).

## Should-fixes

- **Picture flow (fact 10).** C2 sends `{picture:{name, data, no_client_figures}}` (`api.ts:13, 24`); C1 reads `reading` and `no_client_figures` only (`cx_routes.py:636`). Nothing OCRs. Smallest fix in `cx_routes.ask`: `pic = body.get("picture") or {}`; if `pic.get("data")`, `raw = base64.b64decode(pic["data"])`, refuse over 5 MB, `reading = ocr_local.ocr(raw) or ""` (already cached by bytes, engine optional: `available()` false → reading stays empty and Lumen says it used words only); `no_client_figures = pic.get("no_client_figures") is True or body.get("no_client_figures") is True`. The image bytes are never passed further; `_turn` already records `image_sent_to_model: False`.
- **Sharing by name.** The UI's "People or groups, separated by commas" box can only ever produce ids a person does not know. Smallest fix: `cx_dash._reach` resolves a user by `users.id`, `external_identity_id`, `display_name` or `email` the way `b6_run._user_ids` does, and `set_audience` stores the resolved `users.id`. Later a people route for a picker.
- **Duplicate refreshed cards with B4.** `b6_run.notify` (`:237-270`) already writes "Data refreshed · <project>" to every dashboard audience (key `run:<run_id>`), and C3 would write "<title> refreshed · n tiles changed" (key `dash:<id>:refreshed:<token>`) for the same people. Keep one: B4 keeps the failure card to the plan owner and, for a good run, calls `cx_share.notify(plane, pid, did, "refreshed", token=run_id, tiles_changed=…)` per dashboard instead of its own audience loop. Note B4 resolves audience by id/account/name/email while C3 uses `users.id` only; blocker 2 fixes the seed, the name fix above makes both agree.
- **"Why did this move" wired to the wrong route.** `ProjectPage.tsx:126` sends `Why did "…" move?` to `/ask`; use `GET …/tiles/{tid}/why` and show `answer` plus `evidence` as a Lumen bubble. With the demo's one period the answer is "nothing has moved yet"; a second month in the seed would make the demo line worth showing.
- **Silver read of identity tables.** `_allowed` (`cx_dash.py:75-77`) lets a tile `select * from users` (emails, roles) or the access tables, and rows go to the whole audience with no E1d row filter. Exclude `users`, `access_*`, `agent_runs`, `pulse_items` and the audit tables from the silver set (one tuple), or allow silver only through gold.
- **Spec checks.** `check_spec` accepts `transform.calculate` expressions and `href` values. vega-embed runs with `ast: true` (vega-interpreter is installed, so expressions are interpreted, not `eval`ed) and `actions: false`; still, refuse `transform`, `href` and `url`-bearing encodings to keep the spec declarative. `encoding` fields are checked only at the top level; `layer`/`repeat` specs are refused by the mark rule, fine.
- **Tables shape.** UI `GoldTable.refreshed` is never sent; either drop it or C1 adds `last_refresh` (it already computes it in `tile_data`).
- **Route clash on `/centre/consume`** (p3 `ConsumeEntry` vs cxui `ProjectList`) and `ProjectList` using its local picker instead of `s1/ProjectPicker.tsx`: S1 to settle.
- **Permissions.** `cx.permissions.yaml` role names match the other cards' yaml (`company_admin, sponsor, analyst, owner, approver, participant`); the CIO (sponsor) can make dashboards, Finance (approver) can read. Fine.
- **Vega packages.** `vega ^6.4`, `vega-lite ^6.5`, `vega-embed ^7.3` in `ui/package.json`, present in `node_modules` with `vega-interpreter`; tsc passes. Vitest mocks `vega-embed`, so a real render has not been seen; the first vite build and one screenshot will tell.

## What passed as is

SQL guard: multi-statement, DROP/DELETE/INSERT, other project's gold, `read_csv`, `read_text`, `duckdb_tables()`, `information_schema`, `current_setting`, CTE named like a gold table over a foreign table, and a `union all` to a foreign table are all refused; rows capped at 5,000; Decimal/date made JSON-safe. Audience: a user without any E1d reach refused on share; a non-member gets 403 on the dashboard and its data. C3: one card per member with access, none without, once per token.

## Fixes after review (fixer C, 9 Oct)

Driver `.sh-tmp/review_consume.py` re-pointed at the new ids and column names (backup `.bak-v3fixC`); every journey step passes, 0 errors. The only REFUSED lines left are the intended ones (Engineer not in the audience, the SQL and spec probes). - B4 paths and B5 shapes: `api.ts` calls `/dashboards/{did}/tiles/{tid}/...`; `TileCard` takes `did`; ask/decide/share return their real shapes (`{reply, proposals}`, tile, `{audience, refresh}`) and the screen re-fetches the dashboard; `TileData` uses `data_used`; `listDashboards` is typed as summaries.

- Identity tables: `users`, `access_*`, `agent_runs`, `approvals`, `pulse_items`, `audit*`, `documents`, `document_passages`, `extracted_fields` are no longer readable from a tile.
- Spec: `transform` and `href` refused at any depth (`url` and `data` already were).
- Tables shape: `gold_tables` now sends `refreshed`.
- Not mine: blocker 8 (`a5_trail`), the S1 route clash and picker.
