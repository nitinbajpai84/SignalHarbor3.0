# V5W-3: verify, business review, fix, accept (Pipelines step)

Designs C4 to C7.

## Built
- `sh_platform/v1/b9_verify.py`: one record per project (`build/<pid>/verify.json`).
  - Control totals: every loaded batch's `batch_control_totals` (file value against loaded value, recomputed with Decimal and the tolerance), plus each gold table of the copy (rows, and each numeric column's total against the same-named column in the tables it reads from; otherwise "Not compared"). Each figure carries its file name and batch, and an a5 trail link when a stored valuation or position came from that batch.
  - Mark verified: data engineer seat only; refused if any figure differs or nothing was compared; stores who and when.
  - Send for review: needs verified; assigns to the project's business owner (the raiser) as a quiet P1 note (the event). Swap in package 1's assignment model when it lands (one call in `send_for_review`).
  - Review: signed benchmark from `k7_routes.monthly` against the weights in the run's gold benchmark-weights table (`series_key`/`weight`, optional `month`); gaps in points, differing rows flagged.
  - Flag: opens one case (`benchmark_review`) and the owner's words go on it through `n2_comments`. Only the owner (or company admin) flags or accepts. Accept is refused while the mix differs.
  - Fix: proposes the signed mix as a rule version through `e3_rules.propose` (rule `benchmark_mix:<code>`, signed by someone else in the register), then runs the plan on the copy (`b6_run.run` sandbox).
- `sh_platform/v1/b9_routes.py` + `b9.permissions.yaml` (default deny), six routes under `/api/v1/build/p/{pid}/verify`.
- `ui/src/v1/b9verify/` (`VerifyPanel.tsx`, `api.ts`, `verify.css`, `verify.test.tsx`).

## See it
Run the sandbox on a project, open the Pipelines step; the panel shows the control-total table, "Mark this run as verified", the send form, then the review with highlighted gaps, "Send back with this issue", "Fix the benchmark mix and run again" and "Accept the numbers".
