# V5W-4 Delivery step (D1 to D6, BuildDelivery)

## Built
- **Backend** `sh_platform/v1/d1_delivery.py`, `d1_routes.py`, `d1.permissions.yaml` (default deny, one line per route).
  - Channels: Consume (published dashboard), Morning Note section, Slack, Teams, email digest, threshold alert (by email / Slack / Teams / webhook), outgoing webhook.
  - Each channel is a draft by a maker (company_admin, analyst), sent for approval, approved by someone else (head of data, sponsor, approver or company admin; never the maker or submitter; checked in code). Send-back needs a reason.
  - Go live switches approved channels on and sends nothing.
  - Messages are built from the published dashboard's own rows (first row of up to six tiles, printed as the record holds it; no tile rows means "Not available yet", never zero). Alerts compare Decimals.
  - Slack, Teams and webhook addresses are secrets by name: an admin saves the environment variable NAME and the host (`PUT /api/v1/settings/delivery`); the URL is read at send time and never stored, shown or logged. The host goes on a per-company webhook list.
  - Everything that leaves goes through egress: email via the existing `send_email`; webhooks via the new `send_webhook` (https only, host must be on `EgressPolicy.webhook_hosts()`, names tokenised, vault-name and raw-record checks, logged with host only before sending).
  - Outbox (`consume/<pid>/delivery_outbox.json`): every attempt is a row with status sent / held (channel not set up, kept with preview) / blocked (egress refused), a plain reason and the preview. "Send again" retries after setup. Nothing fails silently.
  - Scheduler hook `d1_delivery.tick(plane, now)` and `start(planes)/stop()`: daily/weekly/monthly at a time (default 07:00, reuses `b6_schedule.last_slot`), on change (digest of the figures), alerts at once (once per change of figure).
  - `morning_note_lines(plane, viewer)` for the Morning Note; `summary()` for the project-complete page (lines only from records).
- **Egress edits (shared files, backups in `.sh-tmp/*.bak-v5`)**: `egress/policy.py` + `webhook_hosts()/set_webhook_hosts()`; `egress/gateway.py` + `send_webhook()` appended.
- **UI** `ui/src/v1/d1/`: `DeliveryPage` (D4/BuildDelivery: channel cards, state pills, preview, approve/send back, add a channel, Go live, outbox), `CompletePage` (D5), `SettingsPage` (admin: secret name + host; email state), `api.ts`, `d1.css`, `routes.tsx` (auto-mounted by `v1/index.tsx` glob, Build role gate).

## Mount lines for integration
1. `sh_platform/app.py`: `from sh_platform.v1 import d1_routes` and `app.include_router(d1_routes.router)`.
2. `sh_platform/app.py` startup next to `_install_build_scheduler`: `from sh_platform.v1 import d1_delivery; d1_delivery.start(lambda: [store.plane_for(c) for c in store.list_company_ids()])`; on shutdown `d1_delivery.stop()`.
3. Permissions: add the routes of `sh_platform/v1/d1.permissions.yaml` to whatever aggregates the per-package files into `route_permissions.yaml` (same as b7).
4. Router/shell (package 2): add a "5 · Delivery" step to `b9/steps.ts` and the rail pointing at `/centre/build/p/:pid/delivery`; then change `current="dashboards"` to `"delivery"` in `DeliveryPage.tsx` and `CompletePage.tsx` (the D4 design shows it under "4 · Dashboards and delivery"; StepIcons has no fifth icon, a grid placeholder is fine). "Go live" on Pipelines/Dashboards can link to the delivery page.
5. Settings page: link `/centre/build/delivery-settings` from the shell's Settings (admin only).
6. Consume Morning Note (E1 package): `GET /api/v1/consume/morning-note/delivery-lines` returns `{lines: [{title, lines[]}]}` for approved, live Morning Note channels.
7. Action cards: a channel waiting for approval is `status == "submitted"` in `GET /api/v1/build/p/{pid}/delivery` (`channels[].can.approve` is true for the viewer who may approve).

## Open items
- Channels are fixed once approved (stop and add a new one to change). Editing a draft is not built.
- "Approve in Slack" and replies as comments (plan section 6) are not built; needs an inbound Slack route.
- Message layout is one generic summary; the D4 sentence "ahead of the benchmark by 1.46 points" needs a benchmark-aware template (figures from `k7_benchmark`) and is not hard-coded.
- Teams and Slack get `{"text": ...}`; rich cards and the "Open the dashboard" link need the public base URL setting (not available yet, so the text says where to find it).
- Names are masked by the vault, so a registered person or fund name may appear as a token in Slack and email; this is the egress rule. The preview says so.
- Weekly/monthly use day 1 of the month / Monday default; a day picker is not in the UI.
- Not run: the full backend suite, a live Slack/SMTP check, screenshots (no vite build in this package).
