# V5W-7 Fast, cheap chat replies

## Built
- `sh_platform/v1/chat_fastpath.py`
  - Fixed replies (greeting, thanks, help, who-are-you) for north, span, lumen, flow, tally. No model. Whole-message match only ("thanks, now show me the NAV" goes on to the model).
  - Classifier, cheapest first: fixed, cache, figure, fast tier, strong tier. Rules decide; Jev (`SH_JEV_API_KEY` from the process or `.env`, never printed) only places a question the rules cannot, sees the question with digits and addresses masked and cut to 200 characters, 3 s timeout, 0.6 confidence, answers fast or strong only.
  - Figure answer: a data question whose content words are all in the label of exactly one recorded fact (group of five or more) is answered with that fact, no model.
  - Answer cache: key = agent + company + module + access scope + data version + normalised question + prompt hash. Only a clean answer (done, no guard rewrite, no proposal, no refusal, not JSON mode) is kept; follow-ups ("and last year") are never cached; 15 min, 400 entries. Data version = a counter (`bump(company_id)`) + size/time of the warehouse files, landing folder and `build/*/runs.jsonl`, so a pipeline run or new data invalidates by itself.
  - `ChatStreamMiddleware`: a POST to `/api/v1/**/(chat|ask)` with `Accept: text/event-stream` gets `start`, `delta` pieces, then `done` (same JSON as the plain route) or `error` (status and message). Other clients are untouched.
- `sh_platform/agents/loop.py`: `run_agent(..., fast=None)`; `FP.begin` before the model, `pending.store` after. Nothing is served unless the module is enabled for the company. The number guard still checks every model answer before it is cached.
- `sh_platform/v1/router.py`: `ambiguous()` sends a short lookup (task "answer") to the fast tier.
- `sh_platform/v1/talk.py` (one argument): the company chats pass `fast={"scope": person|roles|project}` so they use the cache.
- `sh_platform/agents/evals/harness.py`: `fast={"off": True}` so evals still test the model and its guard.
- `ui/src/v1/voice/stream.ts` (+ test): `streamChat(path, body, {onStart, onText})` with plain-JSON fallback; `csrfToken` is now exported from `ui/src/api/client.ts`.
- Two old tests that used "hi" as an arbitrary stub question now use "Say hello to the team" (a greeting no longer reaches the model).

## Mount lines (integration)
1. `sh_platform/app.py`, after the other `add_middleware` calls so it is outermost: `from sh_platform.v1.chat_fastpath import ChatStreamMiddleware` and `app.add_middleware(ChatStreamMiddleware)`.
2. Invalidation on writes (optional, the file stamp already catches it): `from sh_platform.v1 import chat_fastpath; chat_fastpath.bump(plane.company_id)` at the end of `b6_run.run` and the landing/load functions.
3. Opt other read-only chats into the cache by passing `fast={"scope": "<who may see this>"}` to `run_agent`. Chats that return JSON, file proposals or change state must not.
4. UI: where a chat composer sends, call `streamChat(path, {text}, {onText})` instead of `apiSend`.
No new routes, so no permissions yaml.

## Open items
- Streaming is of the finished reply cut into pieces, not model tokens: the model client has no streaming call. First words under 1 s hold for fixed, cached and figure replies; real token streaming needs a streaming method on the egress client.
- The Jev call goes straight to the Jev service, not through the egress gateway. It carries only the masked question and is off without a key. The egress reviewer should confirm that is acceptable or route it through the gateway.
- JSON-mode chats (Span, Lumen briefs) get a fixed greeting wrapped as `{"reply": ...}`; the cache and figure answers skip them.
- Other agent names (not the five) get no fixed replies.
