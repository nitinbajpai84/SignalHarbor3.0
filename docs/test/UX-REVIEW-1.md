# UX review 1 · the four centres as a non-technical person meets them

Scope: every screen built this round (shell, Settings, Intent, Action with Today/Cases/Reconciliations/Managers, Build, Consume with dashboards, Office view, CIO Brief, Managers research, Map). Judged on three things: **purpose** (do I know in five seconds what this screen is for and what to do next), **comfort** (plain words, no ids or jargon, sensible defaults, empty states, one main action) and **compatibility** (phone width, keyboard, contrast, the same pattern in every centre). Code read, not run; no code changed.

Severity: 1 = a person is lost or cannot reach the feature; 2 = a person hesitates or is confused; 3 = polish.
Owner areas: A1 shell/settings, A2 intent/SOP, A3 action/today/cases, A4 recon/limits/trade, A5 build, A6 consume/Lumen, A7 office/liquidity/benchmark, A8 managers, A9 map/trail.

## What already works well (keep it)

- Every status is a written word in a pill, never colour alone (`TodayPage.tsx:8`).
- Missing figures read "Not available yet" or name what is missing (`OfficePage.tsx:83`, `k3/HealthTab.tsx:8`).
- Empty states say what will make the screen fill ("No projects yet. Sign an intent of work in the Intent Centre and send it to Build." `b6/ProjectsPage.tsx:23`; `k3/ProcessTab.tsx:18`).
- The follow-up email is a draft to copy, never sent (`ManagersInbox.tsx:70`).
- Agents are named with their role in the chat head (`BuildPage.tsx:103`, `ProjectPage.tsx:119`).
- The workbench already stacks under 760px (`workbench/workbench.css:37`).
