# W1 build: cash and treasury (domain key `cash`)

Cards of the top 50 whose domain is Cash and treasury: 2, 3, 4, 5, 6, 8, 10, 18, 28, 36, 37 (eleven). All eleven have their recipe, signals and test; nine have a new persona build (3 and 36 keep theirs in `role_builds.yaml`).

Files written (and nothing else): `packs/family_office/1/recipes/cash.yaml`, `packs/family_office/1/signals/<card id>-*.yaml` (21 files after wave 2), `packs/family_office/1/builds/cash.yaml`, `tests/v1/test_w1_cash.py`, this page.

Test run: `python -m pytest tests/v1/test_w1_cash.py -q` gives **61 passed, 0 failed** (about 50 seconds after wave 2). Expected numbers in the tests are read from `answer_keys.yaml`, or worked out from the office files in the test (card 2's fee for Credit III call 3), never typed.

How the test works: the model's own DDL (`docs/v2/evidence-to-action-mvp.duckdb.sql`) in an in-memory DuckDB; small readers load the office6m files (csv, xlsx with openpyxl, pdf text with pypdf) into the model's tables; each recipe is rendered by `v3_recipes.render`, its tables checked with `v3_recipes.refusal` (the tables rule), run, compared with the key, and its tie-out run with `v3_recipes.tie_out`. Signals are checked and fired with the engine's own `check`, `resolve`, `calc` and `render` over the recipe rows.

## Needs (for the fixers; nothing below was done by me)

1. **Real loader.** Not called; the test has its own small readers. The platform loader must produce: documents `capital_call_notice`, `distribution_notice`, `fund_terms` with extracted fields `call_amount`, `due_date`/`pay_date`, `management_fee` (absent when "none in this call"), `bank_account`, `management_fee_rate`; call and distribution notices as `cash_movements` (calls negative, `noticed` then `confirmed`, `due_date`, `notice_kind`, `commitment_id`); bank credits as `confirmed` distribution rows with `bank_account_id` and no `notice_kind`; capital call payments as `payment` rows; transfers with `counterparty_portfolio_id`; payee `bank_accounts` from `standing_instructions.csv` (`verified_on` = confirmed_on) and a superseding unverified row when a notice names a new account; office accounts with `cash_instrument_id`; the register as `commitments` (`called_to_date` at `called_as_at`).
2. **Double counting.** `cash_by_entity` sums instruments of type `cash`. The bank accounts' cash instruments must be another type (the test uses `bank_balance`) or the administrator's cash and the bank balance would be added together.
3. **No payment reference.** `cash_movements` has no reference column, so the recipes cannot return STA-2609, FEE-CUST-Q3, CALL-C-7 or the intercompany reference IC-2026-08-01 (the card 28 key has it). Add a column, or add `source_records` (external_record_id) to `may_read` of `payment_batch` and `intercompany_balance`.
4. **Signed rules the loader must create** from `office_rules.csv` (A20): `cash_buffer` {amount, currency}, `payment_approval` {amount, currency}; and two that the office6m data does not hold, so the figures stay held or the signal skipped until a person signs them: `bank_limit_<bank as lower-case words joined by _>` {max_pct} (the policy sets none) and `fx_plan_tolerance` {pct} (the 0.1 percent is in card 6 and its key only).
5. **Holds on payments.** `payment_batch` shows a held invoice from an open `approvals` row of type `payment_hold` (rationale = reason). The invoice check of card 50 must write it. Amounts: calls are stored negative (A5); the recipes use the absolute value, so either sign works.
6. **Signal engine.** (a) A figure input without `by` is a list of rows and a condition cannot read a list, so `uc-010-bankexp-over-limit` and the funding signals use literal `by` values (`worst: 1`, `is_named: true`); a `foreach` or a one-row summary would be cleaner. (b) `date_passed` items are needed for `administrator_cash_file` (only while the file is missing) and for distribution notices (the layout must name its pay date with "due" in the field name, see `dated_items`). (c) Layout field names assumed: capital_call_notice [fund, investor, amount, currency, call_no, due_date]; distribution_notice [fund, amount, currency, pay_date]; invoice [payee, amount, currency, due_date]; fx_confirmation [trade_reference, currency_bought, currency_sold, amount_sold, rate]. (d) New hold names (`record_call`, `release_payment`, `offer_transfer`, `report_uncalled`, `close_distribution`, `close_fx_match`, `move_cash_to_bank`, `state_cash_as_current`) are enforced by nothing yet; only `prepare_payment` is.
7. **Existing tests that now fail** (not mine; adding signals and recipes changes what they count): `tests/v1/test_v3_signals.py` three tests expecting the five-signal library; `tests/v1/test_v3_recipes.py` four tests (the list of seven built recipes; the binding question now exceeds the egress size limit with about 50 recipes, `payload_too_large`; one assertion on all recipes needs `never_read`, which `renewals_vendors` and `invoice_variance` from other builders lack).
8. **`call_no`** is the trailing digits of the notice reference, which is not unique across funds (CEDA/2026/005 is both Cedarpoint funds' call 5); every lookup also keys on the fund.
9. **Card 6, second and third parts** (conversions without a bank confirmation, M09; call status after the bank statement) are not built here: they need the bank-side conversion rows matched with `fx_confirmations`, which `fx_confirmation_variance` does not cover.
10. **Card 36 key.** `role_builds.yaml` still expects 13,450,000 for `uc6-uncalled`; the office6m key says 14,600,000 (15,850,000 before call 7). I did not touch it.
11. **Overlap.** `uc-005-benefcheck-hold` and `uc01-bank-changed` can both fire on call 7; the first fires only while the recipe finds no recorded call-back. `uc-004-callcheck-no-source`, `uc-028-interco-lender-short` and `uc-028-interco-offer` split on `best_other_spare` (none, partial, enough) so only one of them fires for a call; `uc-018-fundplan-under-buffer` fires whenever a transfer is possible, next to the offer or the partial-lender card, so the CFO may see two cards for one short call.
