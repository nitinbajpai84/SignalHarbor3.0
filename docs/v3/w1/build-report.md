## What the test does

The office files are loaded into an in-memory DuckDB with the company model (`docs/v2/evidence-to-action-mvp.duckdb.sql`) by a small loader inside the test (the platform loader does not read the office6m files yet; see Needs 2). Each recipe's SQL is rendered the way `v3_recipes.render` does and run. Each recipe also passes the A8 check (`v3_recipes.refusal`: it reads only the tables it names), and its tie-out holds. Each signal is checked with the real engine (`v3_signals.check`, `parse`, `calc`, `render`) and evaluated on rows of the built recipe tables, with the same rule as the engine's `resolve`: a declared field that is empty skips the signal.

## Needs (for the fixers and the other builders)

1. **Tests that will fail when the wave is merged (not mine alone).** `tests/v1/test_v3_recipes.py::test_recipes_load_from_the_domain_folder...` asserts the built set is exactly the seven original ids; with the new recipes it must list all ready ids. `test_a_figure_is_matched...` fails on the one-line check `all(r.get("may_read") and r.get("never_read") is not None ...)`: every ready recipe of the wave must carry `never_read` (mine do; another domain's does not). `test_three_north_names...` and `test_a_recipe_the_question_names...` also fail after the wave (cash-break names; a recipe's `names` now match a question). `tests/v1/test_v3_signals.py` (three tests) asserts the library is exactly the five UC01 signals. I did not edit them.
2. **Loader.** The platform loader does not read the office6m files. The test loader's mapping is the one to build: administrator `Positions` sheet into `position_snapshots` (`view_type` accounting, `position_date` the pack's "As of", `as_of_at` the valuation date, `data_status` as written, rows "Not received" skipped); issued reports into `documents` (type investment_report, `document_date` the month end, `received_at` the issue time) with one `extracted_fields` row per line (assumption A3); the audit request into `documents` (type audit_request) with `report_month`, `line`, `figure` fields on the item number as `line_number`; manager statements for Fund A into `valuation_observations` (the amended one supersedes the estimate); the policy into `business_rules` and `rule_versions`; the benchmark workbook into `benchmark_definitions` and `benchmark_components`; index files into `market_observations` (`index_level`; the March month end comes from the workbook, the daily files start on 1 April) and the WMR fixing (`fx`); custodian trades into `transactions` (buy cash negative, sell positive); the notice of call 7 into `cash_movements` (noticed); the fund teaser into `deal_pipeline`. Data points the loader must handle: one custodian row writes its date day first (`10/07/2026` in `transactions_2026-07.csv`); funds F, G and K are in the administrator pack but not in the security master (no class, no manager).
3. **Rule codes and parameters (A20).** The policy PDF names its limits `limit_single_name_liquid`, `limit_listed_equity_liquid`, `limit_manager_entity_b`, `limit_hedge_funds`; A20 says `allocation_<asset_class>`. The recipes read the parameters, not the code: `rule_type` policy, `approval_status` approved, `parameters` with `portfolio` (the portfolio code), `dimension` (`single_name`, `asset_class` or `manager`), `bucket`, `min_pct`, `max_pct`, optional `target_pct`. The rules loader must write that shape. The materiality rule is `cio_materiality` with `{amount, pct}` (policy section 6: 100,000 USD or 0.5 percent). A proposed limit is a second `rule_versions` row of the same rule with another `approval_status` (proposed); `limit_changes` tests it, every other recipe ignores it.
4. **Sovereign note exempt from the single-name limit (fixed in wave 2, the rule is still to be signed).** The key and the committee notes leave the sovereign treasury note (7.08 percent) out of the 5 percent limit; the policy text (section 3, "any single name", 0 to 5 percent) does not. The recipes no longer match the name "sovereign". A holding is exempt only when a signed rule exists: a `business_rules` row of type policy with parameters `{portfolio, dimension: single_name_exempt, instrument}`. With none on record the note is a breach like any other (test `test_a_holding_is_exempt_only_when_a_signed_rule_says_so`). The test loader writes that row as a stand-in, with a comment saying so; the office has to sign the real one.
5. **Stale-value days.** The 90 days come from the card (`uc5-limits`), not from a signed rule. The recipes read a rule `stale_value_days` with `parameters.days` and use 90 when there is none. Sign it and the fallback goes.
6. **Data finding on the single-name limit.** By the September data seven names are above 5 percent: Harborview Semiconductor 5.75, Coastal Rail Holdings 5.64, Larkspur Health 5.46, Juniper Consumer Brands 5.38, Evermore Banking Group 5.29, Atlas Harbour Shipping 5.13, Northwind Logistics 5.08. The key and the October committee note name only Harborview (the key says 1 real breach for card 47). `single_name_breach` lists all seven, the largest first; the test asserts Harborview as the key says and records the count. The key should say whether the other six are breaches. The October note also says Cedarpoint 56.50 percent of EG-B-OPS and hedge funds 54.95 percent; the administrator pack (and so the key) gives 26.73 and 54.55, because the pack puts fund C in EG-PRIVATE.
7. **Attribution mapping.** Asset class to index series (listed_equity: Global Equity Index, bond: Global Bond Index; a class with no index, such as the convertible with no class, has a 0 benchmark return) is written in the recipe. The liquid sleeve is the components of the approved benchmark with no spread, rescaled to 100 percent (60 / 40). Both should be a signed mapping or part of the benchmark definition. The recipe shows only portfolios whose classified holdings all have an index (the liquid book).
8. **Return method.** Modified Dietz with flows weighted half, as the key does. A flow is a buy or a sell of the portfolio; income is not a flow and is not in the return (the `income` column shows it; key method kept, for Nitin to decide). The data starts on 1 April, so the year to date and the 12 months are returned with `complete = false`. Month ends come from the administrator packs; they equal the custodian files for the six months. Wave 2: a month has a return only when no value at either end is carried forward or estimated, all holdings are in the base currency, the previous month end is the previous calendar month and the holdings did not change without a trade; else the return is empty and `data_note` says why. A benchmark is applied to a portfolio only through a signed rule `benchmark_link` with `{portfolio, benchmark_code}` (the model has no link; the loader writes one for EG-LIQUID as a stand-in).
9. **Names.** The report line "Evergreen Liquid Book" is the portfolio EG-LIQUID; the test loader sets that portfolio name. `report_tie_out` and `report_ready` match a line to the administrator by exact instrument or portfolio name and take administrator rows by `view_type = 'accounting'`; if the loader uses another view type for the administrator the two recipes need it.
10. **Trace coverage** checks the file and page only. The "run" and "definition" the card mentions (calculation run, `metric_evidence`) are not read.
11. **Signal inputs that no recipe holds** (the watchers must pass them in the event's `doc`, as the other domains' signals do): `days_since_issue` (a daily tick with today's date), `was_outside` (last month's drift), `previous_version` and `version_number` of a benchmark file, `stated_return_pct` of a quarter, `done` and `days_to_committee` of a pack section, the cash figures of the morning note (`entity`, `call_amount`, `due_in_days`, `shortfall`, from the cash builder's `cash_after_calls`), and the committee waiver (`expires_on`, `days_past_expiry`, `breach_open`): `committee_decisions` has no expiry column, so the expiry has to come from `conditions` or an extracted field.
12. **Committee decisions.** `pack_items` counts an amendment as open when no `committee_decisions` row has `subject_type = 'valuation'` and the valuation's id, and a breach as open when none has `subject_type = 'breach'` and the holding name. Those two subject types are my convention; nothing writes the table yet. Section owner roles in `pack_items` (cio, investment_analyst, risk_officer, cfo) follow the key's owners.
13. **Recipe names.** `drift_vs_target` deliberately avoids the phrase "allocation drift", which an existing test requires to match no recipe.
14. **Shared scratch folder.** The six builders write helper scripts into the same session scratchpad; one of my generators (`gen_signals.py`) was overwritten by another builder's file of the same name. My generated files are intact and tested; use a per-builder subfolder if a script must be re-run.
