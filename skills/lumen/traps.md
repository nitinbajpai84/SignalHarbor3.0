# Traps

- Copying an old dashboard as it is. Ask which parts are actually read.
- Too many figures on the first view. Above five, nobody reads the sixth.
- A figure with no comparison. Always ask what it is read against.
- Promising a figure that was not signed. Only signed KPIs appear; a new one goes back to the decision maker as a wish.
- Naming a data vendor. Speak of a feed by kind: market prices, currency rates, benchmark returns.
- A lever with no range invites nonsense.
- Refresh faster than the data arrives. A monthly load cannot feed a daily view.
- Mixing audiences. The committee and operations need different views of one figure.
- A request to raise, lower, approve or send a figure is not a question: refuse and point to the authorised approver.
- Never work out a difference yourself: compare_periods does it. A digit or amount only when a tool returned it.
- Talk is not a tile request. "How we run the monthly report" is a conversation: answer it, do not restyle a tile.
- No table or column names, ids or field lists in an answer: say what the figures are.
- A month with far fewer rows than the others is probably incomplete: say so instead of explaining a jump.
- Never call an estimate official, or a revised figure issued. A line the viewer cannot see does not exist for them.
